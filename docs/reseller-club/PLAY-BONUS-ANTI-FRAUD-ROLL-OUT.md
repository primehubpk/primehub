# PrimeHub Reseller cash wallet & Rs.100 Play Store bonus — approval checklist

Work branch: `feature/reseller-wallet-admin-dupes-oct14`. No deployment or main merge authorized. No production user was credited. Play bonus is **OFF by default**.

## Wallet rules (read these before testing with real funds)

**Withdrawal Balance** = `reseller_profiles/{uid}.walletAvailable`: reward cash can either be withdrawn (minimum Rs.500, with existing admin approval), or spent on store orders. **Shopping-only Cash** = server-controlled `reseller_shopping_wallets/{uid}.balance` mirrored into `reseller_profiles.walletShopping`: available only for store orders; cannot be withdrawn. **Total Cash for Shopping** = withdrawal balance + shopping-only cash. Points are not money.

When a customer elects to pay by wallet, the checkout Firestore transaction **spends shopping-only funds first, then withdrawable funds**; any unpaid amount remains COD. Both balances and the order and spend ledger commit atomically. Cancelling a not-yet-shipped order restores the exact original sources atomically, once only. Never count total shopping cash as an extra third balance. Standard checkout remains unchanged and does not fetch a wallet balance on regular quotes.

## App bonus verification (NOT a regular web reward)

- User must install the actual PrimeHub Android v12+ app **from Google Play**, open its Wallet tab, be signed in with the existing Reseller Club Firebase account, and deliberately tap **Verify & Claim Rs.100**. A website, Chrome, laptop or mere Android user-agent string cannot verify an install. Download counts alone aren't proof of usage.
- New native `PlayBonusManager` requests a Google Play Integrity **classic** attestation using a unique server-created one-time nonce. Server calls Google's `decodeIntegrityToken` API and checks matching package/nonce/freshness, Google-recognized Play app, licensed installation and device integrity. Untrusted apps, APK sideloads, unsupported devices, stale challenges or failed Google verification never award money.
- Native Android uses `Settings.Secure.ANDROID_ID`, a scoped app-signing-key/user/device ID, **NOT IMEI**. Server stores **HMAC-SHA256 keyed hashes only**, one claim per Firebase UID AND one per app-scoped Android ID, using a Firestore transaction. No raw device ID, serial number, phone/IMEI, advertising ID, user fingerprint or hardware ID is saved.
- Approved claim adds Rs.100 to `walletAvailable` (withdrawable cash); minimum withdrawal remains Rs.500, so Rs.100 alone cannot be withdrawn. Server creates immutable audit event `reseller_wallet_credits/play-install:{uid}`.
- `PLAY_INSTALL_BONUS_ENABLED=true` opt-in **only after** policy review, signed v12+ release tested and Play Integrity API credentials configured. Keep `PLAY_BONUS_DEVICE_HMAC_SECRET` ≥32 secret random characters, server-only, stable between deploys; changing it changes device hashes and can reopen bonus eligibility. Existing `FIREBASE_SERVICE_ACCOUNT_KEY` must have Google Cloud / Play Integrity API access and be permitted to call Play's decode endpoint.
- Play Integrity must be linked to the correct `com.primehubmall.app` Play Console/GCP project; the Play release must be signed with the SAME production key and have appropriate integrity services available. The current branch CI only builds **unsigned/debug APK** and does NOT publish or activate payouts. End-to-end attestation validation needs an actual Google Play installed production/in-app test track build.
- **Google Play developer policies must be reviewed for cash incentives tied to app install and Play integrity/account licensing.** Do not market, promote, deploy or enable this reward before that policy review; financial fraud and legal/tax considerations may apply.
- If Google Play's Device Recall feature is available and approved, use it for stronger fraud prevention after reinstall/factory reset. Currently this code **reads** an optional used bit if returned but does not request or write Device Recall state. Android ID can change after factory reset, signing-key changes, user profiles and some reinstalls. Device one-time enforcement is therefore strong against simple reinstall/account-switch with same ID but not fraud-proof.

## Spin & Win across devices

There is **no universal IMEI for browsers and computers**. Android 10+ apps are prohibited from collecting IMEI by normal Play Store permissions, and web browsers cannot access device serial/IMEI. Browser-local guest ID allows one wheel spin per Pakistan calendar day across account switching **in that browser**; Firestore atomic browser + account daily locks reduce races/duplicate payouts. Clearing browsing data, switching browsers or using another device changes the local browser ID; this is not a universal cross-device identifier. Account-level restriction continues across the same account's devices. Chrome guest mode is an unverified preview; rewards still need server-verifiable claims.

The old `/rewards` page previously minted points, spins and guest wallet migrations directly in browser and Firebase. On this branch, official signed-in check-in/spin and redemption routes now verify amounts and owner server-side; guest-only local preview points CANNOT be converted to real account points by editing localStorage. Update and deploy hardened `firestore.rules` together with the backend; **do not deploy the rules by themselves** or old production clients could lose reward actions.
