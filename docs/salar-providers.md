# Salar provider settings

Admin → Salar, or the admin drawer in Salar chat → AI provider / model.
The normal PrimeHub admin password session is used for provider settings and
credentials. There is no separate Google verification step.

Cloudflare is the default first provider, using `@cf/google/gemma-4-26b-a4b-it`.
Requests explicitly send `chat_template_kwargs.enable_thinking=false`.
Select Cloudflare, Groq, Gemini or OpenRouter; enter a text model ID and save.
The connection test only calls the selected provider and never hides a failure
behind fallback. Other vendors' models can be used through OpenRouter if supported.
Adding a separate API vendor still requires a server adapter.

API keys are managed from the Admin panel only. Enter up to nine keys, one per
line, in fallback order. New nonblank input replaces this provider's saved keys;
blank input retains them. Removing saved keys leaves that provider unconfigured
until keys are added again. Cloudflare account ID is also saved from Admin.
Provider API keys and Cloudflare account ID do not fall back to Vercel variables.

Apply `supabase/migrations/20260920_salar_provider_secrets.sql` before deploying.
The dedicated table denies public/anon/authenticated access. Only the service
role can read/write it. Each provider row has an AES-256-GCM encrypted envelope,
with provider-bound authentication and random nonce. Cached DB reads contain
ciphertext; plaintext is decrypted server-side only. API responses expose counts,
account ID and status only. Saves invalidate the shared cache.

Encryption derives a purpose-specific HKDF key from `SALAR_KEYS_ENCRYPTION_KEY`
if set, otherwise the existing `SUPABASE_SERVICE_ROLE_KEY`. Keep this root stable.
Before rotating that root, re-encrypt saved rows under the new root or re-enter
provider keys after rotation. No secret belongs in NEXT_PUBLIC_ variables.

Catalogue/admin instructions retain the existing tagged cache; admin saves and
refreshes invalidate it. Chat replies are generated by the model from admin
instructions, not canned sales responses. API latency and platform quotas still
apply.

Validation: `node --test tests/salar-*.test.mjs` (Node 24).
